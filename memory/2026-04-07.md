### Fix 1: Channel Post Retry Spam (main.py + telegram_handler.py)
**Bug**: When bot restarts outside working hours, stale `channel_post` tasks from the DB get executed. `post_channel_summary()` returns `{'success': False, 'message': 'Outside working hours...'}`. The task handler treated this as a retriable failure → 3 retries → "permanently failed" ERROR log spam.
**Root cause**: No distinction between "transient failure" and "non-applicable condition".
**Fix**:
- Added `'skip': True` flag to non-retriable returns in `telegram_handler.py` (lines 588, 601)
- `_handle_channel_post_task` in `main.py` now checks `results.get('skip')` and returns `True` (completed/skipped) instead of `False` (retry)
- Uses a structured flag, not fragile string matching (per verifier feedback)

### Fix 2: Stale Reminder Duplicate Prevention (database_v2.py + main.py)
**Bug** (from previous iteration, uncommitted): `_maint_v2_stale_check` fetched all pending reminders and filtered in Python — missed already-sent reminders, causing duplicates for unresolvable chat IDs.
**Fix**: Added `has_recent_reminder(client_id, source, hours)` method to `database_v2.py` that checks both pending AND sent reminders within a 24h window via SQL.
