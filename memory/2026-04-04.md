## Anthropic API Outage & Cron Fleet Recovery

### Problem
Anthropic API (profile `anthropic:team-records-bot-v2`, OAuth token, Max subscription) started timing out around 03:00. All 13 cron jobs using `anthropic/claude-sonnet-4-6` failed with `timeout` errors for 6+ hours.

### Root Cause
The token itself is valid (OAuth, `subscriptionType: "max"`, not expired). The issue is intermittent timeouts — likely rate limiting or routing issues between Google's subscription billing and Anthropic's API. This is a Google-subscription-routed token, not a direct API key.

### Fix Applied
1. Gateway reconfigured with fallback chain: Gemini 3.1 Pro → Gemini 2.5 Pro → Gemini 2.5 Flash → Ollama (josiefied-7b)
2. All 12 active pipeline-engineer cron jobs switched from `anthropic/claude-sonnet-4-6` to free Gemini models:
   - Routine monitoring (Service Sentinel, Git Guardian, Session Janitor, Build Canary, Morning Briefing, RAG Refresh, Tool Audit, Dependency Patrol, Dev Journal): `google-gemini-cli/gemini-2.5-flash`
   - Deep thinking (Self-Critique, Hunt & Improve, Weekly Analysis): `google-gemini-cli/gemini-3.1-pro-preview`
3. All 5 Shark/Windows cron jobs disabled (Windows OpenCode is DOWN — shark's problem)

### Lesson
NEVER hardcode a single paid model for cron jobs. Always use free models for routine work, paid models only for interactive sessions where quality matters. Cron jobs must be resilient to API outages.

Design principles learned:
- SHORT prompts for Gemini Flash (it chokes on 1000+ line context)
- LONGER timeouts (120s minimum, 600s for complex work)
- Gemini Flash for monitoring/simple tasks ONLY
- Sonnet for anything requiring reasoning or file manipulation
- Opus reserved for interactive sessions (don't waste on crons)
- Max 4 concurrent agents — never schedule overlapping jobs
- Silent delivery for maintenance tasks to reduce noise

## Self-Improvement Session (23:30)

### Issues Found & Fixed

1. **RAG model mismatch (CRITICAL)** — embeddings.jsonl had 768-dim vectors (nomic-embed-text) but all query scripts (query.sh, search.sh, index.py) referenced mxbai-embed-large (1024-dim). Cosine similarity between different dimensions = garbage results. Search was completely broken.
   - Fix: Standardized everything on nomic-embed-text (768-dim). Reduced chunk size from 3000→2000 chars to avoid CJK token overflow. Added 4000-char truncation safety + 3-retry logic.
   - Rebuilt index: 287 files, 2,432 chunks, 0 errors, 37.3MB (was 59,450 chunks / 915MB with old index)
   - Verified: search returns relevant results with 0.57–0.68 similarity scores ✅
